# Store assets

The App Store screenshots and preview are generated, not drawn. Start `node tools/store/worker.mjs`, which answers the demo from `seed.json`, the question Sonnet asked and the notes Opus wrote in one real run, so the captures need no provider keys and come out the same every time, and run the store suite on an iPhone 17 Pro Max simulator with the Demo row hidden: `TEST_RUNNER_OOOOH_WORKER_URL=http://127.0.0.1:8790 xcodebuild ... -only-testing:oooohUITests/StoreCaptureTests -resultBundlePath store.xcresult test`. `export-captures.sh store.xcresult <captures>` copies the screenshots out by name, and `render.sh <captures> <out>` serves `shots/*.html` over the site's CSS and the orb canvas and screenshots each one with headless Chrome: the numbered templates at 1206 by 2622 for the iPhone slot App Store Connect requires, and at 1320 by 2868 and 1284 by 2778 for the optional large display slots, and the product-page artwork, `header-3840x1646.png` from `header.html`, `search-3840x2560.png` from `search-sunrise.html`, `search-centred-3840x2560.png` from `search.html`, and `universal-5244x2950.png`, cut from the header for both slots. Each screenshot template is one caption of at most seven words over a phone frame drawn in CSS with the real capture inside. For the preview, run each test method on its own with `xcrun simctl io <device> recordVideo <name>.mov` running alongside, write `shots.tsv` beside the clips (clip, start second, duration, caption, tab separated, one row per shot in `storyboard.md`), and `preview.sh <clips> <out.mp4>` cuts them into the 886 by 1920, 30 fps, silent stereo file App Store Connect accepts. To refresh the seed, run the Worker with its keys (`npm run dev -- --port 8791` in `worker/`), start `node tools/store/worker.mjs --record http://127.0.0.1:8791`, and run `testSessionMoments` against port 8790 once; the stand-in forwards every request, prints each provider route's usage, and writes `seed.json` when the notes come back. Rendered files stay out of the repo.
